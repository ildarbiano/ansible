Требования к Информационной Системе

Информационная система должна соответствовать условиям, решать задачи описанным ниже.

1. Описание

Стенд для тестирования настроек базы Postgres и Nginx, как балансировщика нагрузки. Нагрузка создаётся генератором случайных числе и подаётся на стенд, генератор нагрузки регулируется по RPS в процентном отношении. Стенд управляется java-приложением с целью создания задержек на тракте от генератора до базы данных.

2. Бизнес-логика

  • Генераторы создают нагрузку на базу данных;
  • GUI позволяет управлять нагрузкой и создавать замедления, а также является визитной карточкой проекта с вложенной документацией;
  • Мониторинг позволяет обеспечивать наблюдаемость компонентов системы;
  • Сценарии и роли Ansible позволяют обеспечить развёртывание и настройку компонентов системы.

3. Технические задачи

  1. Развернуть стенд с использованием Ansible (подготовка инфраструктуры). Обеспечить два типа нагрузки для тестирования различных сценариев:
    • POST: подгрузка данных в Postgres через генератор нагрузки к сервису БД;
    • GET: через генератор нагрузки к сервису БД.
  2. Обеспечить возможность:
    • регулировки интенсивности подаваемой нагрузки;
    • замедления обработки запросов на приложении Java.
  3. Настроить мониторинг (Prometheus + Grafana) для визуализации всех компонентов.

4. Требования к технологиям и инфраструктуре

Вся система и стенд:

  • Разворачивается Ansible;
  • Строится на VirtualBox;
  • Имеет доступ в открытый интернет;
  • Упакован в Docker;
  • Использует: Nginx, Tomcat, Postgres.

5. Функциональные требования

5.1 Описание процессов
  • Посредством Ansible разворачивается система стенда, все компоненты;
  • Запускается и наблюдается мониторинг;
  • Запускается нагрузка;
  • Нагрузка регулируется по параметрам: величина нагрузки и задержка/замедление приложения бизнес-логики.
5.2 Описание клиентских путей
  • Пользователь → Nginx (443) → Node.js (3001) (GUI);
  • Пользователь → Nginx (443) → Tomcat (8080) (Java-приложение);
  • Tomcat → PostgreSQL (5434) (запросы к БД).
5.3 Прототипы пользовательских интерфейсов

GUI реализован на Node.js и доступен по адресу: https://192.168.0.55/ui/

  • Вкладки с документацией (ТИС, АИС, РАИС);
  • Регуляторы нагрузки (GET/POST запросы/сек, таймаут);
  • Панель метрик приложения.
5.4 Требование к мониторингу

Prometheus + Grafana. Метрики для сбора:

Источник Метрики
Java (Micrometer) RPS, latency (p50, p95, p99), количество ошибок, размер кэша, GC время
Postgres Exporter Количество активных сессий, размер таблиц, количество блокировок
Nginx Ingress Количество запросов, HTTP статусы, размер ответа
Node Exporter CPU, память, диск

Дашборд в Grafana:

Раздел Панели
Общий RPS по эндпоинтам, Latency (p95), HTTP 5xx
Детальный (Java) Heap Memory, GC Pause, Threads
Детальный (Postgres) Active connections, Query duration, Cache hit ratio
Нагрузка RPS от k6, Response time
5.5 Требование к журналированию

Журналирование не требуется.

6. Нефункциональные требования

  • Обеспечить нагрузку от 1 до 10K rps;
  • Обеспечивать задержку отклика от 0 до 10 сек.
